`docs/06-elevation.md`(18번 줄)와 `docs/08-guidelines.md`(21번 줄, DON'T)는 한때 이 프로젝트의 그림자 시스템을 "폰 프레임(최상위 스테이지) `0 40px 80px rgba(0,0,0,.5)`"로 정의해뒀는데, 2026-09-22 저녁 커밋에서 `.container`(구 `.phone`)에 실제로 적용된 값은 `box-shadow: 0 8px 32px rgba(20, 21, 26, 0.12)`였다 — offset-y·blur·불투명도 세 값 모두 문서 스펙과 달랐다(Major). 코드가 문서보다 오래돼서 생긴 드리프트가 아니라, 새로 추가된 코드가 기존 문서 규칙을 어기고 들어온 사례였다.

**해소(같은 날 재검토):** 사용자가 코드 값(`0 8px 32px rgba(20,21,26,.12)`)을 명시적으로 의도한 값이라고 확인 → 코드는 되돌리지 않고 대신 `docs/06-elevation.md`·`docs/08-guidelines.md` 두 곳 모두 스펙 문구를 코드 실측값으로 갱신, "폰 프레임" 표현도 `.container`로 정리. 두 파일을 직접 읽어 갱신됨을 확인(06번 18행, 08번 21행). 이 케이스는 "코드가 틀렸다"가 아니라 "문서가 낡았다"로 판정한 것 — 다음에 유사 불일치가 나오면 코드가 최근에 의도적으로 바뀐 것인지부터 사용자에게 확인하고, 그렇다면 문서를 코드에 맞추는 방향을 우선 고려할 것.

**참고(미해결로 남은 부분):** `.ticket` 요소는 여전히 box-shadow가 없어(06번 문서의 티켓 스펙 `0 24px 48px rgba(0,0,0,.35)` 미구현), "2단계 그림자" 엘리베이션 시스템의 티켓 쪽 절반은 아직 코드로 구현되지 않은 상태다. 향후 티켓에 그림자가 추가/변경되면 06번 스펙과 대조할 것.

**Why:** body와 `.container`의 배경색이 같은 커밋에서 같아졌으므로([[color_doc_sync_rule]] 참고), 카드 구분을 그림자에만 의존하게 됐다 — 다만 이 판단(값의 강도)은 사용자의 명시적 디자인 결정이었으므로 리뷰어가 되돌릴 사안이 아니라 문서를 맞추는 사안이었다.

**How to apply:** `.container`/`.ticket`의 `box-shadow` 값이 바뀌는 CSS 변경을 리뷰할 때마다 `docs/06-elevation.md`·`docs/08-guidelines.md`의 스펙과 라인 단위로 대조한다. 값이 다르면 먼저 "의도된 변경인지"를 확인하고, (a) 의도된 변경이면 두 문서를 코드에 맞춰 갱신했는지 확인, (b) 의도치 않은 값이면 Major로 지적해 문서 스펙으로 되돌리도록 요구한다.
