사용자가 "약 2초~3초 있다가 나오도록 해줘"처럼 구체적인 시간 범위를 명시하며 진입 애니메이션을 요청하면, 실제 비동기 데이터(API 응답, Realtime sync 등)가 도착하는 시점에 애니메이션을 연동시키지 말고 그 시간 그대로 고정 딜레이(`setTimeout`이나 CSS `animation-delay`)로 구현한다.

**Why:** [[project_count-chip-entrance-animation]] 작업에서, "처음엔 안 보였다가 2~3초 후 노출"이라는 요청을 "급격한 변화 방지" 원칙에 따라 실제 Supabase Realtime Presence의 첫 `sync` 이벤트(진짜 데이터 도착 시점)에 연동시켰다. 인위적 지연은 UX 안티패턴이라 판단했기 때문. 하지만 로컬 환경에서 sync가 수백ms 만에 도착해 "2~3초 숨김" 효과가 거의 느껴지지 않았고, 사용자가 같은 요청을 "약 2초~3초 있다가 나오도록 해줘"로 다시 명확히 반복했다 — 즉 사용자가 원한 건 데이터 로딩 상태 표현이 아니라, 접속 시 일정 시간 뒤 나타나는 연출 자체였다.

**How to apply:** 사용자가 구체적 시간 범위를 제시하며 "N초 후 나타나게/사라지게" 등을 요청하면, 먼저 고정 딜레이로 구현한다. 실제 데이터 로딩 완료 시점에 맞추고 싶다는 의도가 명확할 때만(예: "로딩 끝나면", "데이터 오면") 비동기 트리거를 쓴다. 애매하면 고정 딜레이 쪽을 기본값으로 삼을 것 — 더 예측 가능하고 사용자가 지시한 시간 그대로 재현된다.
