애매하게 표현된 시각적 요청(예: "여기 가독성이 좋게 만들어줘", "더 크게")을 받으면, 무엇이 문제인지 스스로 추측해서 바로 CSS를 고치지 말고 AskUserQuestion으로 2~4개의 구체적인 해석 후보(예: "크기/간격 대비 부족" vs "색상 대비 부족" vs "아이콘 굵기 문제")를 제시해 확인부터 받는다.

**Why:** 이 프로젝트에서 `mcp__claude-in-chrome__*` 브라우저 자동화 도구가 세션 내내 한 번도 정상 연결되지 않아, 실시간으로 렌더링 결과를 직접 확인할 방법이 없다. 이 환경에서 추측성 CSS 수정을 반복했다가 사용자가 여러 번 정정해야 했던 전례가 있다(이 세션 압축 이전 구간). 반대로 "규리 → 가 함께 기도하고 있어요" 폰트 크기처럼 이미지가 함께 제공되고 요청이 명확한 경우엔 바로 수정해도 문제없었다.

**How to apply:** [[user-screenshot-driven-iteration]]과 함께 적용 — 사용자가 스크린샷/참고 이미지를 첨부했고 요청이 명확하면(예: "바코드를 스탬프로 바꿔줘", 참고 이미지 첨부) 바로 구현. 이미지 없이 형용사만으로 표현된 요청("가독성 좋게", "더 낫게")이면 반드시 먼저 후보를 제시해 확인받는다. 이 규칙은 Chrome 자동화가 정상 연결되기 시작하면(직접 렌더링 확인이 가능해지면) 완화할 수 있다.
