이름 검색 기능을 테스트하다가 "병훈" 검색이 아무 결과도 안 나와서 버그라고 의심했는데, SQL로 직접 조회해보니 해당 행(`id=126`)이 내가 복원해둔 "병훈이형"에서 "병소정"으로 또 바뀌어 있었다 — 내가 모르는 다른 세션(실제 사용자 또는 테스트 중인 사람)이 그 사이에 같은 라이브 DB를 통해 수정한 것. 리스트 화면의 "N명이 보고 있어요" 배지([[realtime-presence-viewer-count]])가 이미 암시하고 있던 사실이다.

**Why:** 목데이터라고 해서 고립된 샌드박스가 아니다 — 실제 이벤트용 앱이 가리키는 그 DB에 직접 쓰기 테스트를 했고, 그 결과는 지금 접속해 있는 다른 모든 사람에게 그대로 보인다.

**How to apply:** ① 기능을 수정/삭제/검색 테스트할 때 쓰는 이름·값은 테스트 직전에 SQL로 현재 상태를 다시 확인하고 시작할 것(이전 세션에서 적어둔 값을 그대로 믿지 말 것). ② 테스트용으로 실명 데이터를 바꿔야 한다면, 끝나고 반드시 원상복구하되 복구 직후 값도 그대로 유지된다고 가정하지 말 것. ③ "기대와 다르다"는 결과가 나오면 먼저 내 코드 로직을 의심하기 전에 `mcp__supabase__execute_sql`로 실제 현재 DB 값을 찍어서 내가 보는 화면이 최신 상태인지부터 확인할 것([[verify-db-changes-empirically]]의 연장선).
