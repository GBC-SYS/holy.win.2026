`#screen-ticket`의 상단(뒤로가기 버튼+이름, `.ticket-hero`)과 하단(관계/제출일/상태 그리드+스탬프, `.ticket-wrap`)은 **서로 다른 카드로 분리되어 각자 그림자/모서리를 갖고, 그 사이(와 좌우)에 `--bg` 베이지 배경이 비치는 틈이 보이는 게 의도된 최종 구조**다.

**어떻게 이 구조로 정착했는지:** 원래는 완전 풀블리드(카드 개념 없이 화면 전체가 이어짐) → 사용자가 보딩패스 참고 이미지를 주며 "상단 부분을 그림자로 구분되게, 모서리 둥글게" 요청 → `.ticket-hero`를 여백+둥근 모서리+그림자를 가진 카드로 분리(이때 `.ticket-wrap`도 자체 모서리를 가진 별도 카드가 됨) → 사용자가 "여기랑 여기랑 분리되어 있잖아 붙여줘"라며 **하나의 카드로 합쳐달라고 명시적으로 요청** → 정확히 그 요청대로 `.ticket-hero`+`.ticket-wrap`을 감싸는 `.ticket-card` wrapper로 병합(이음매 없이 색상만 바뀌는 하나의 카드) → 사용자가 곧바로 "붙여줘의 이미지 그게 아니였어! 다시 이전 상태로... 주황색 상단 영역과, 하단 흰색 영역이 구분되도록"이라며 **병합을 취소하고 다시 분리해달라고 요청** → `.ticket-card` wrapper를 제거하고 `.ticket-hero`/`.ticket-wrap` 각자 그림자·모서리를 갖는 구조로 되돌림. [[feedback-post-approval-redesign-expected]] 2026-09-23 추가 사례가 이 경위 전체를 기록하고 있다.

**Why:** 사용자가 원하는 최종 형태는 "보딩패스처럼 색이 다른 두 섹션이 시각적으로 나뉘어 보이는 것"이지, 단일 카드 안에서 색만 바뀌는 것이 아니다. 참고 이미지를 줬다고 해서 그 이미지의 해석이 한 번에 맞아떨어지는 건 아니라는 사례이기도 하다.

**여백 값은 계속 바뀌는 중(고정된 스펙 아님):** `.ticket-hero`의 margin은 `16px 16px 20px`(4방향 모두) → `16px 0 0`(위만) → 삭제(margin 없음, 좌우도 카드가 꽉 참) → 다시 `0 16px`(좌우만, "여백이 너무 없다"는 피드백으로 복원)까지 같은 세션 안에서 여러 번 바뀌었다. `.ticket-wrap`도 동일하게 `margin: 0 16px`를 갖는다(둘이 같은 폭을 유지해야 위아래가 시각적으로 어긋나지 않음). **이 메모리는 "분리된 두 카드"라는 구조적 결정만 신뢰할 것 — 정확한 margin/radius 픽셀값은 항상 `assets/css/entries.css`의 `.ticket-hero`/`.ticket-wrap`을 직접 읽어서 확인할 것.**

**How to apply:** 앞으로 이 화면에서 "상단/하단이 분리돼 보인다"는 보고를 받아도 그 자체를 버그로 추정해 병합하려 들지 말 것 — 오히려 의도된 상태다. 반대로 "하나로 이어져 보이면 좋겠다"는 요청이 다시 오면, 과거에 `.ticket-card` wrapper로 병합했다가 바로 되돌려진 전례가 있다는 걸 알고 있되, 이번엔 정말 원하는 걸 수도 있으니 [[feedback-post-approval-redesign-expected]]의 태도(방어하지 않고 그대로 반영, 스크린샷으로 직접 검증)로 접근할 것.
