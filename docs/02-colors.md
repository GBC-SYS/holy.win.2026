# 02. Colors — 색 7개

## 채우는 칸

```
## Colors
| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 바탕 | #f3efe6 (--bg) | 화면 배경 |
| 표면 | #ece7db (--card-muted) | 카드, 시트 |
| 글자 기본 | #141413 (--ink) | 제목, 본문 |
| 글자 보조 | #6e6b64 (--muted) | 날짜, 부가 정보 |
| 테두리 | #e6e1d5 (--line) | 구분선 |
| 포인트 색 | #e8622c (--accent) | 주 버튼, 선택된 상태에만 |
| 포인트 색 옅은 것 | #fceae0 (--accent-soft) | 선택된 칩 배경 |

바탕과 표면 중에 바탕이 더 밝다.
```

색 공간은 **HEX**로 통일한다 (코드가 이미 HEX로 작성되어 있음). 바탕/표면 관계는 방식 A(밝은 바탕 + 한 단계 어두운 표면, 카드가 눌린 느낌)를 쓴다.

**강조 표면(예외):** `--paper (#ffffff)`는 위 "표면"과 별개로, 화면에서 가장 중요한 콘텐츠(티켓 상세, "이번 주 제출" 카드)에만 쓰는 순백의 예외 표면이다. 바탕과 표면 둘 다보다 밝게 두어 스포트라이트처럼 튀게 만드는 의도적 선택이며, 이 표면 위의 텍스트도 글자 기본(`--ink`)을 그대로 쓴다 — 라이트 테마로 전환하면서 텍스트 색을 표면에 따라 반전시키던 규칙은 없어졌다(08번 가이드라인 참고).

**글자 보조 색 주의:** 다크 테마에서 쓰던 `#8a8783`을 그대로 가져오면 새 밝은 바탕(`#f3efe6`) 위에서 대비가 약 3.1:1로 떨어져 아래 4.5:1 기준에 못 미친다. `#6e6b64`로 낮춰 4.6:1 이상을 확보했다 — **다크 테마의 색 값을 라이트 테마에 그대로 재사용하지 말 것.**

**코드에 남아있는 추가 색(7개 밖의 예외, 늘리지 않는다):**
| 값 | 쓰는 곳 |

| #e5e3df | 티켓 안쪽 점선 구분선 |
| #a6a39e | 그리드 라벨(`.grid-label`) 등 아주 옅은 보조 텍스트(대비가 낮은 편이라 향후 개선 후보). 리스트 카드 제출일(`.entry-date`)은 대비 문제로 `var(--muted)`로 교체해 이 예외에서 빠졌다 |

| #1f7a37 (--success) / #e3f5e6 (--success-soft) | 상태 배지(`.status-badge--done`/`.entry-status--done`, "완료") 전용 예외 색. `--success` on `--paper` = 5.39:1, `--success` on `--success-soft` = 4.74:1 — 둘 다 4.5:1 기준 통과. 초기값(#3f6b3a/#dddfd1)이 어둡고 탁하다는 피드백으로 더 밝고 선명한 톤으로 교체함(대비 기준은 유지). 07번 "상태 색은 7색 밖 예외(최대 3색)" 조항에 해당하며, 현재 "성공" 1색만 등록되어 있다(경고/오류는 미구현) |
| #dc2626 (--destructive) / #ffffff (--destructive-foreground) | 위험 버튼(`.btn-danger`, 티켓 상세 화면의 "삭제") 전용 색. 티켓 삭제는 되돌릴 수 없는 동작이라 `showDialog({ danger: true, showCancel: true })` 커스텀 다이얼로그(백드롭 탭으로 안 닫힘, 07번 참고) 확인 단계를 거친 뒤에만 호출된다. `--destructive` 배경 위 `--destructive-foreground` 글자 대비를 WCAG 상대 휘도 공식으로 직접 계산: `#dc2626`의 상대 휘도 ≈ 0.1672, 흰색(#ffffff)의 상대 휘도 = 1.0 → 대비비 = (1.0+0.05)/(0.1672+0.05) ≈ **4.83:1**, 4.5:1 기준 통과. "상태 색"(성공/경고/오류)과는 별도의 "위험 색" 카테고리이며 09번 `--destructive`/`--destructive-foreground` 값과 동일하다 |

## 작성 규칙

- **딱 7개.** IBM Carbon, Shopify Polaris, 무지시 실험 모두 실제 화면 1장에는 7~9개 색만 쓰임. 더 정해도 대부분 "있으면 좋은" 수준
- **포인트 색은 1개만.** 브랜드 색을 꼭 버튼에 쓸 필요 없음 — 브랜드 색은 로고/일러스트, 버튼은 "눌러야 할 곳"을 알려주는 역할만
- **바탕/표면 밝기 관계를 반드시 한 줄로 명시.** 안 적으면 화면마다 카드가 떴다 가라앉았다 함
  - 방식 A: 밝은 바탕 + 한 단계 어두운 표면 (카드가 눌린 느낌, IBM 방식)
  - 방식 B: 어두운 바탕 + 한 단계 밝은 표면 (카드가 뜨는 느낌, Shopify 방식)
  - 방식 C: 바탕과 표면을 같은 값으로 두고 테두리로만 구분 (shadcn 방식 — 이때는 "밝기 차를 두지 않는다"라고 적을 것)

## 값을 정하는 기준 (어떤 색을 고르든 공통)

구체적인 색은 브랜드에 맞게 직접 정한다. 다만 **칸 사이의 관계**는 아래를 지켜야 화면이 무너지지 않는다.

| 칸 | 어떤 값을 넣나 |
|---|---|
| 바탕 | 화면에서 가장 넓은 면. 채도를 거의 주지 않는다 (줘도 아주 미세하게) |
| 표면 | 바탕과 **명도 차 2~6%** 정도. 차이가 크면 카드가 둥둥 뜨고, 0이면 테두리가 반드시 필요 |
| 글자 기본 | 바탕 대비 **명도 대비 7:1 이상** (WCAG AAA) |
| 글자 보조 | 바탕 대비 **4.5:1 이상**. 이보다 옅으면 "흐린 게 아니라 안 보이는" 글자가 됨 |
| 테두리 | 바탕과 글자 보조 **사이**의 명도. 글자보다 진하면 선이 내용을 이김 |
| 포인트 색 | 화면에서 **유일하게 채도가 높은 색**. 위에 흰 글자든 검은 글자든 4.5:1이 나오는 명도로 |
| 포인트 색 옅은 것 | 포인트 색의 **10~15% 톤**(또는 바탕과 섞은 값). 그 위에 포인트 색 글자를 얹어도 읽혀야 함 |

## 방향 고르기 (값은 직접 정하되, 성격은 아래에서 하나를 고른다)

| 방향 | 색의 성격 | 바탕↔표면 | 포인트 색 |
|---|---|---|---|
| 무채색 / 절제형 | 채도 0에 가까운 회색조만 사용 | 방식 A | 채도를 낮게, 또는 무채색 그대로 |
| 난색 / 따뜻함 | 바탕·표면에 미세한 온기를 섞음 | 방식 B | 채도 높은 난색 |
| 다크 | 바탕은 **완전 검정을 피하고** 어두운 무채색으로 | 방식 B | 어두운 배경 위에서 대비가 확보되는 밝기로 |
| 테두리 중심 | 바탕=표면 동일 값 | 방식 C | 자유 (배경 구분을 테두리가 전담) |

- **다크 테마 주의:** 순수 검정(#000000)은 글자와 대비가 과해 눈이 피로해짐. 바탕은 검정보다 조금 밝은 값으로 둔다
- **다크 테마 주의:** 라이트 테마의 색을 그대로 반전시키면 포인트 색이 탁해짐 — 포인트 색은 명도를 올려 따로 정한다

## 색 공간 — HEX와 OKLCH 중 하나만

- **HEX**: 디자인 툴에서 바로 집어오기 쉬움. 대신 명도를 눈으로 맞춰야 함
- **OKLCH**: 밝기(L)를 고정한 채 색상만 바꿔도 체감 명도가 유지됨. 포인트 색만 교체해 여러 프로젝트에 재사용할 때 유리 (→ `09-shadcn-tokens.md`)
- 둘을 **섞어 쓰지 않는다.** 한 프로젝트 안에서 표기법이 갈리면 값 비교가 불가능해짐
