# 06. Elevation — 깊이

## 채우는 칸

```
## Elevation
- 깊이는 [그림자 / 배경색 차이 / 테두리] 하나만 쓴다
- (그림자라면) 카드 그림자 [                              ]
- (그림자라면) 뜬 요소(모달 등) 그림자 [                              ]
- (배경색이라면) 그림자를 쓰지 않는다. 카드는 배경색 차이로 구분한다
- (테두리라면) 그림자와 배경색 차이를 쓰지 않는다. 카드는 테두리 [__]px로만 구분한다
```

레이어별로 나누는 경우 (아래 "예외" 참고)
```
## Elevation
- 화면에 붙어있는 요소(리스트 카드, 버튼, 입력창) — 그림자 없음. 절제 카드(entry-card--dark)만 테두리 1px(--card-muted-line)로 구분, 강조 카드는 표면색 자체로만 구분(hover 시 포인트 색 테두리)
- 화면 위에서 강조되어 뜨는 요소(최상위 컨테이너) — 그림자 1단계: `.container`(페이지 최상위 스테이지) `0 8px 32px rgba(20,21,26,.12)`
```

절충(레이어 분리) 방향을 채택했다. 일상적으로 붙어있는 요소는 그림자를 쓰지 않아 화면이 평평하고 절제되어 보인다. 티켓 상세 화면은 풀블리드로 리디자인하며 그림자를 없앴다가, 이후 "상단 주황 영역(topbar+ticket-head)만 떠 있는 카드처럼 보이게 해달라"는 요청으로 `.ticket-hero`에 그림자 1개(`0 12px 28px rgba(20,21,26,.18)`)를 다시 얹었다 — 그 대신 `.container`는 이 화면에서 자신의 그림자를 끈다(`:has(#screen-ticket...)`), 두 요소가 겹치면 이음매에 이중 그림자가 생기기 때문이다. 즉 티켓 화면에서는 그림자 책임이 `.container`에서 `.ticket-hero`로 옮겨간 것이지, 그림자 자체가 사라진 게 아니다.

**예외 — 유리질감(glassmorphism) 레이어:** 배경 사진(`assets/imgs/list-bg.jpg`) 도입 이후, 그 사진 위에 얹히는 표면(리스트 카드 `.entry-card`, 칩·탭, 주 버튼, 티켓 화면의 카드/배지/시트/다이얼로그)에는 위 "화면에 붙어있는 요소는 그림자 없음" 규칙과 별개로 `--glass-shadow`(`0 10px 24px rgba(58,20,8,.16)`, 02번/09번 참고) 1단계와 상단 하이라이트 그라디언트(`--glass-sheen`)를 공유해서 쓴다. 사진 위에서 표면의 경계(어디까지가 카드인지)를 알아보게 하려면 그림자·하이라이트가 최소한으로 필요하기 때문이며, 값은 모든 유리질감 표면이 동일한 토큰을 공유해 임의로 늘어나지 않는다. 사진 배경이 없는 일반 화면/요소는 이 예외 대상이 아니다.

## 작성 규칙

- **셋 중 하나만 고른다.** 그림자·배경색 차이·테두리 모두 맞는 방법이지만 **안 정하는 게 문제** — 안 정하면 AI가 화면마다 다르게(홈은 그림자, 목록은 테두리) 씀
- **안 쓰기로 했으면 "쓰지 않는다"고 명시.** 그림자 얘기를 아예 안 적으면 AI는 기본값(그림자 있음)으로 채움. **빈칸 ≠ 안 쓴다는 뜻**
- **예외 — 레이어로 가르는 것은 허용.** "화면에 고정된 요소는 테두리만, 화면 위에 떠서 다른 요소를 가리는 요소만 그림자"처럼 **기준이 한 문장으로 설명되면** 두 방식을 함께 써도 일관성이 유지됨. 기준 없이 섞는 것만 금지

## 값을 정하는 기준 (그림자를 쓰기로 한 경우)

| 칸 | 어떤 값을 넣나 |
|---|---|
| 카드 그림자 | 아래로 아주 조금(1~2px), 번짐도 작게, 불투명도는 낮게. 화면에 늘 깔리는 그림자라 진하면 금방 지저분해짐 |
| 뜬 요소 그림자 | 아래로 더 크게, 번짐도 크게. 카드 그림자와 **한눈에 구분될 만큼** 차이를 둘 것 |
| 그림자 색 | 검정 계열에 낮은 불투명도. 채도 있는 색 그림자는 쓰지 않는다 |
| 단계 수 | **2단계까지만.** 3단계 이상은 화면에서 구분이 안 되면서 값만 늘어남 |

- **다크 테마에서는 그림자가 거의 안 보인다.** 다크로 갈 거면 깊이를 배경색 차이나 테두리로 잡는 편이 낫다
- **그림자와 배경색 차이를 같은 요소에 함께 주지 않는다.** 둘 다 "떠 보이게" 하는 장치라 겹치면 과해짐

## 방향 고르기

| 방향 | 어떤 방식 |
|---|---|
| 플랫 / 절제형 | 배경색 차이 — 그림자를 쓰지 않는다 |
| 입체감 / 커머스·모바일 앱 | 그림자 — 배경색 차이를 쓰지 않는다 |
| 구조 중심 / 정보 밀도 높은 화면 | 테두리 — 그림자와 배경색 차이를 둘 다 쓰지 않는다 |
| 절충 (권장 예외) | 붙어있는 요소는 테두리, 뜨는 요소만 그림자 |

## 레이어 정리 (절충형을 고를 경우 그대로 옮겨 적을 것)

| 레이어 | 그림자 | 테두리 |
|---|---|---|
| 카드, 버튼, 입력창 | 없음 | 있음 |
| 드롭다운, 툴팁, 선택 목록 | 옅게 | 있음 |
| 모달, 시트 (화면을 덮는 것) | 진하게 | 선택적 |

## 체크리스트
- [ ] 세 가지(그림자/배경색/테두리) 중 정확히 하나를 골랐는가 — 또는 레이어 기준을 한 문장으로 적었는가
- [ ] 나머지는 "쓰지 않는다"고 명시했는가
- [ ] 그림자를 쓴다면 단계가 2단계 이내인가
- [ ] 다크 테마인데 그림자에 의존하고 있지 않은가
